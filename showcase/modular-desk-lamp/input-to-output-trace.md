# Input-to-Output Trace

> Transparent build trace for a fictional demonstration. This document maps supplied or generated material to the finished pages; it is not a claim that a real design project was completed.

## What changed

| Before the Skill workflow | After the Skill workflow |
|---|---|
| One fictional concept brief | A 14-page case story with an explicit thesis and ending |
| No user or engineering evidence | Every claim remains E0, caveated, or marked `to_validate` |
| No page plan | Each page answers one review question using a registered layout |
| No visual asset register | Seven generated visuals have declared origins and allowed uses |
| No validation result | A future test plan identifies reach, tipping, joint effort, and glare questions |
| No credibility record | Manifest and source notes expose authorship, assumptions, and missing proof |

The workflow improved structure and disclosure. It did not increase the evidence level.

## Reproduction path

1. Install the Skill and start a new Agent session.
2. Give the Agent the `input/` folder.
3. Use `input/reproduction-prompt.md`.
4. Review the proposed evidence inventory and gating questions before allowing page production.
5. Generate or supply visual assets only after the story and disclosure boundaries are locked.
6. Validate the manifest, HTML, layouts, and behavior rubrics.
7. Compare the result with `storyboard.md`, `source_notes.md`, and the current `index.html`.

## What this example does not prove

- performance on a real, messy project archive;
- accuracy of project selection for a job or school;
- quality of an unsupervised first draft;
- consistency across different Agent runtimes;
- any product, user, engineering, manufacturing, or commercial outcome.

A separate sanitized real-project forward test is still required for those claims.
